# The VarCat paradigm

Human-readable companion to [`paradigm/vocabulary.json`](../paradigm/vocabulary.json). The JSON is the source of truth: the plugin, the validator and the tests read it, never this page. If the two disagree, the JSON wins and this page is the bug.

## Why

Aviala Design's Figma Variables grew organically. The exported ALD collections carry three different casings, plural and singular forms side by side, leaves that repeat their own group (`border/border-fail-primary`), names with spaces (`border-radius-extra-small 2`) and two vocabularies for the same idea (`fail` vs `error`, `infomation` vs `info`). Nothing could be generated, validated or diffed.

VarCat replaces that with one closed vocabulary per slot, five namespaces and a validator, so a variable name is either derivable from the paradigm or it is a violation.

## Global naming rules

| # | Rule | Legal | Illegal |
|---|------|-------|---------|
| 1 | Charset is `a-zA-Z0-9-`, plus `/` as the group separator | `text/theme-primary` | `text/theme_primary`, `text/theme primary`, `text/theme.primary` |
| 2 | Every segment and every slot starts with a lowercase letter; inside a slot, compound words are camelCase | `noBackground`, `bottomDeep`, `s8` | `LightBackground`, `lightbackground`, `8` |
| 3 | A group is mandatory, and its first segment is the namespace layer | `primary/s8` | `s8` |
| 4 | The leaf must not repeat the full group name | `button/filled-primary-background-rest` | `button/button-filled-…`, `effect/effect-top` |
| 5 | Singular only | `button` | `buttons` |
| 6 | Every slot draws from a closed list; the same word in another slot is not automatically legal | `size/md` | `size/medium` (`medium` is a `weight` step) |
| 7 | `-` only separates slots | `box/theme-soft` | `box/theme-light-background` |

Rule 4 compares against the whole group segment, not a prefix: `neutral/s1` is fine even though `neutral` is also a palette family.

Rule 5 is enforced conservatively: a slot is only reported as plural when dropping the trailing `s` lands on a word the vocabulary already knows. That rejects `buttons` while leaving `xs`, `canvas`, `focus`, `progress` and `thickness` alone.

## Namespaces

One Figma Variable Collection per namespace. `scaleDensity`, `scaleContrast` and `scaleStatic` are three collections that share one key set, so a density switch is a collection swap rather than a mode that competes with light/dark.

| Collection | Path shape | Value | Modes | Count |
|------------|------------|-------|-------|-------|
| `palette` | `{family}/{step}` | literal `COLOR` | `light` / `dark` | 74 |
| `semantic` | `{use}/{tone}-{slot}` | alias → `palette` | `light` / `dark` | 150 |
| `scaleDensity` | `{category}/{step}` | literal `FLOAT` | `default` | 59 |
| `scaleContrast` | `{category}/{step}` | literal `FLOAT` | `default` | 59 |
| `scaleStatic` | `{category}/{step}` | literal `FLOAT` | `default` | 59 |
| `component` | `{type}/{component}-{level}-{role}-{state}` | alias → `semantic` | `light` / `dark` | 344 |
| `effect` | `effect/{name}-{position}` | literal `COLOR` | `light` / `dark` | 6 |
| `effectSwitch` | `effect/{name}-{position}` | literal `COLOR` | `on` / `off` | 6 |

757 variables in total for a full Apply. The dependency direction is `palette → semantic → component`, with `scale*` and `effect*` feeding components as literals:

```
palette  {family}/{step}
   ↓
semantic {use}/{tone}-{slot}
   ↓
component {type}/{component}-{level}-{role}-{state}
   ↑
scale*   {category}/{step}        effect*  effect/{name}-{position}
```

### palette

Families: `primary` `success` `warning` `error` `info` `neutral`.
Steps: `s1`…`s12` for the chromatic families, `s1`…`s14` for `neutral`.

Steps are written `sN`, not `8`, because rule 2 requires a leading lowercase letter. The display name in Figma and the docs still speak of step 8; only the path is `s8`.

Chromatic ramps are generated by `@aviala-design/color` with the ALD options (8 hue families protected, strength 2, gamma 1), the same call ColorCat makes, so the same seed lands on the same hex. The neutral ramp is the Aviala Design Colors literal ramp, kept verbatim rather than re-approximated.

### semantic

`use` ∈ `border` `box` `control` `text`
`tone` ∈ `theme` `normal` `success` `warning` `error` `info`
`slot` ∈ `primary` `secondary` `tertiary` `soft` `muted` `canvas` `inverse` `onColor` `title` `caption` `focus` `disabled`

`use` narrows `slot` (the `use × slot` matrix in the vocabulary):

| use | slots |
|-----|-------|
| `text` | `primary` `secondary` `tertiary` `muted` `inverse` `onColor` `title` `caption` `disabled` |
| `box` | `primary` `secondary` `soft` `canvas` `inverse` `muted` |
| `border` | `primary` `secondary` `tertiary` `soft` `focus` |
| `control` | `primary` `soft` `muted` `canvas` `inverse` |

`tone` selects the palette family: `theme` → `primary`, `normal` → `neutral`, everything else keeps its name. `fail` and `infomation` are gone.

The full alias table lives in [`paradigm/aliases/semantic-to-palette.json`](../paradigm/aliases/semantic-to-palette.json) and keeps the ALD semantic step map: background/border/control primary → step 8, text primary → 10, secondary → 7, tertiary (ALD "light") → 5, box secondary → 4, soft → 2.

Both modes normally alias the *same* palette variable, because the palette collection already flips per mode. The exception is `onColor`, text on a filled brand surface, which must stay near-white in both themes and therefore points at `neutral/s1` in light and `neutral/s14` in dark.

The neutral rows keep ALD parity too: `control/normal-soft|muted|primary` → neutral 3/4/6 (ALD `control-normal-lightBackground-1|2`, `control-normal-Background-3`), and `border/normal-soft|tertiary|primary` → neutral 3/4/6 (`border-normal-1|2|3`). That makes neutral's quiet surfaces sit slightly above the chromatic tints; it is parity, not an accident.

### scaleDensity / scaleContrast / scaleStatic

`category` ∈ `size` `gap` `padding` `radius` `thickness` `lineHeight` `weight` `transparency`

`category` narrows `step`:

| category | steps |
|----------|-------|
| `size` `gap` `padding` `radius` `lineHeight` | `none` `xs` `sm` `md` `lg` `xl` `xxl` `xxxl` `max` |
| `thickness` | `none` `xs` `sm` `md` `lg` |
| `weight` | `light` `semilight` `regular` `medium` `semibold` `bold` |
| `transparency` | `loading` `disabled` `placeholder` |

All three collections carry the identical 59 keys and differ only in value:

- **scaleStatic** — the baseline, carried over from ALD `base-numbers` Default.
- **scaleDensity** — comfortable / touch density, carried over from ALD `base-numbers` Mobile Friendly: larger type, line-height and spacing.
- **scaleContrast** — accessibility pass: same geometry, thicker strokes, heavier weights, more opaque disabled states.

Values: [`density.json`](../paradigm/scales/density.json), [`contrast.json`](../paradigm/scales/contrast.json), [`static.json`](../paradigm/scales/static.json).

### component

`type` ∈ `button` `input` `checkbox` `radio` `switch` `select` `tag` `tab` `link` `badge` `toast` `dialog` `menu` `card` `tooltip` `progress` `slider` `avatar` `divider` `icon`
`component` (the variant) ∈ `filled` `outlined` `ghost` `soft` `text`
`level` ∈ `primary` `secondary` `tertiary` `danger` `success` `neutral`
`role` ∈ `background` `foreground` `border` `icon` `label` `focusRing`
`state` ∈ `rest` `hover` `active` `focus` `disabled` `loading` `selected` `checked`

The cross product is 20 × 5 × 6 × 6 × 8 = 28 800 paths, which is not a design system. Only the whitelist in [`paradigm/matrices/component.json`](../paradigm/matrices/component.json) is created: 344 entries covering `button`, `input`, `checkbox`, `switch`, `link` and `tag`. The remaining types keep their vocabulary reserved — a path like `avatar/filled-primary-background-rest` is vocabulary-legal but reported as `notWhitelisted` until a recipe exists.

The Figma group is `{type}` and the leaf is the other four slots, which is what keeps rule 4 satisfied.

Each whitelist entry carries its semantic alias, derived from `role` → `use`, `level` → `tone` and `(variant, state)` → `slot`:

- `background` resolves to `control` for interactive types and to `box` for surfaces.
- `foreground` / `label` / `icon` resolve to `text`, and on a `filled` variant to `text/{tone}-onColor`.
- `border` / `focusRing` resolve to `border`, and `focusRing` always to `border/{tone}-focus`.

Example: `button/filled-primary-background-rest` → `semantic/control/theme-primary`; `button/filled-primary-foreground-rest` → `semantic/text/theme-onColor`.

`hover` and `active` on a filled control currently alias the same semantic token as `rest`, because ALD has no hover step in the semantic layer. That is deliberate: the variable exists so a designer can override exactly one value, and the interaction delta stays in the component layer instead of being faked in the ramp.

### effect / effectSwitch

`name` ∈ `glow` `lineShadow` `softLight` `rim` `bloom`
`position` ∈ `top` `bottom` `all` `bottomDeep` (only `lineShadow` uses `bottomDeep`)

The group is literally `effect`, so the leaf carries `{name}-{position}` and never repeats `effect`. Both collections use the same paths; `effect` switches by theme (`light`/`dark`) and `effectSwitch` switches by feature flag (`on`/`off`, where `off` is fully transparent — how ALD `special-effort` OFF disables an effect).

Default enabled set (from ALD's five `special-effort` tokens plus `softLight-all`): `glow-top`, `glow-bottom`, `lineShadow-bottom`, `lineShadow-bottomDeep`, `lineShadow-all`, `softLight-all`. The Dry-run/Apply UI can expand every legal pair (16) on request.

## Validation

`src/paradigm/validate.ts` is pure — no Figma API, no IO — so the plugin, the dry-run CLI and vitest all agree. It reports issues by code:

| Code | Meaning |
|------|---------|
| `illegalChar` | rule 1 |
| `emptySegment` | empty path segment |
| `missingGroup` / `tooManySegments` | rule 3 |
| `slotCase` | rule 2 |
| `pluralSlot` | rule 5 |
| `groupEcho` | rule 4 |
| `slotCount` | wrong number of leaf slots for the namespace (also what rule 7 violations look like) |
| `unknownSlotValue` | rule 6, value is in no closed list |
| `matrixViolation` | rule 6, value is legal elsewhere but not for this key |
| `notWhitelisted` | `component` path outside the matrix |
| `unknownNamespace` | no namespace owns this group and slot count |

`validateVariablePath` classifies a path when no collection is given, which is what the plugin's **Validate selection** report uses on an existing file. The three scale collections and the two effect collections are the same shape by design, so classification can only name the group they belong to; pass the namespace explicitly when the collection is known.

Gold and anti examples for every rule live in [`tests/validate.test.ts`](../tests/validate.test.ts).
